# IndicF5 — the eleven Indian languages — on top of requirements.txt.
#
# Kept out of requirements.txt for the reason written at the bottom of that
# file: several gigabytes of torch that the demo container, which only ever
# speaks English through Piper, would pay for on every `pip install -r`. The
# Dockerfile installs this in a separate `indic` stage, so `docker build` with
# no --target still produces the lean image.
#
# ## Why f5_tts is NOT installed from here
#
# `ai4bharat/IndicF5` is loaded with `trust_remote_code=True`, and the
# `model.py` that comes down with the weights calls
#
#     load_model(DiT, dict(...), mel_spec_type="vocos", vocab_file=..., device=...)
#
# with no checkpoint path. **No release of `f5-tts` on PyPI has ever accepted
# that call** — every one of them, 0.3.4 through 1.1.22, takes `ckpt_path` as a
# required positional argument, so the load dies with
#
#     TypeError: load_model() missing 1 required positional argument: 'ckpt_path'
#
# AI4Bharat vendored a modified f5_tts in their own repository, where
# `load_model` has no `ckpt_path` and loads the weights from the safetensors
# instead. `model.py` puts its own directory on `sys.path` expecting to find it
# beside itself — but transformers only downloads the modelling file, not the
# package next to it, so the import falls through to whatever `f5_tts` is
# installed. That is why the Dockerfile installs their fork
# (https://github.com/AI4Bharat/IndicF5, package `f5_tts` 0.1.0) directly, and
# why it does so with `--no-deps`: their setup.py pins `numpy<=1.26.4`, and
# opencv-python — under rapidocr, which is how this service reads documents —
# requires numpy>=2. One of the two has to give and it cannot be OCR, so their
# dependencies are listed here by hand instead, minus that pin.
#
# ## CPU wheels, and why the index URL is not optional
#
# A bare `pip install torch` on Linux resolves to the CUDA build: ~2.5 GB of
# nvidia-* wheels for hardware this container does not have and, on the demo
# box, could not use anyway — `tts/config.yaml` pins `indicf5.device: cpu`
# because Ollama is holding the 4 GB of VRAM.
--extra-index-url https://download.pytorch.org/whl/cpu

torch
torchaudio

# torchaudio 2.11 does not decode anything itself any more: `torchaudio.load`
# delegates to torchcodec, and without it the fork's `infer_process` - the last
# call before audio comes back - raises
#
#   ImportError: TorchCodec is required for load_with_torchcodec.
#
# It reads the reference wav, so it is on the path of every Indic synthesis.
# torchcodec links against the ffmpeg the Dockerfile already installs for
# faster-whisper.
torchcodec

# 4.49.0 is what the model's config.json names, and the fork's own
# requirements.txt says `transformers<4.50`. It is a hard edge, not caution:
# from 4.50 the model is built on the meta device and the custom model.py,
# which constructs real tensors in its __init__, dies at the first synthesis —
# not at import — with
#
#   RuntimeError: Tensor on device cpu is not on the expected device meta!
#   NotImplementedError: Cannot copy out of meta tensor; no data!
#
# so /health reports all eleven languages ready and every one of them 503s.
transformers==4.49.0
